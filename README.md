# 우리집 베이킹랩

Node.js 24 이상에서 실행하는 로컬 제과제빵 웹입니다. 코드의 주요 처리에는 한국어 주석을 달았습니다.

## 바로 실행

Windows에서는 `실행하기.cmd`를 더블클릭하세요. 현재 작업 폴더에는 의존성이 이미 설치되어 있습니다.

주소: http://127.0.0.1:3210

직접 실행할 때는 이 프로젝트 폴더에서 다음 명령을 사용합니다.

```powershell
npm install
npm run db:setup
npm run dev:local
```

서버가 실행 중인 동안 파일을 수정하면 개발 서버가 변경 내용을 반영합니다. 서버 창에서 Ctrl+C를 누르면 종료됩니다. 배포 명령은 포함하지 않았습니다.

## 어디를 수정하나요

| 파일 | 역할 |
| --- | --- |
| `components/App.tsx` | 공통 메뉴, 홈, 추천, 주방, 레시피, 계산기, 베이크 모드 |
| `components/ExtraScreens.tsx` | 실험실, 자료실, 트렌드, 기록, 도전, 관리자, AI 화면 |

| `lib/domain.ts` | 재료 판정, 단위 변환, 원가, 팬 크기, 대체 계산 |
| `lib/db.ts` | 로컬 SQLite 저장과 자료 조회 |

| `lib/integrations.ts` | 실제 RSS 수집과 AI 외부 요청 |

수정하기 쉬운 일반 CSS와 Node 내장 SQLite를 사용했습니다. PRD의 기술 기본안 중 Tailwind·Prisma 대신 사용한 부분이며, 저장 데이터는 `data/baking.sqlite`에 있습니다. 원본 JSON을 수정해도 관리자에서 공개한 덮어쓰기 기록이 있으면 DB의 수정본이 우선합니다.

## 체험과 데이터

상단 프로필에서 `체험용 주방`을 고르면 예시 재료·도구·가격으로 살펴볼 수 있습니다. `나의 주방`은 직접 입력하는 별도 공간입니다. 가격은 실제 시세가 아닌 예시입니다.

레시피는 원문 배합과 공정을 대조한 교육용 자료이며 실제 제조·전문가 검증은 하지 않았습니다. 출처와 원본에서 바꾼 부분은 `content/SOURCES.md`와 각 레시피에 기록했습니다. 가상 실험은 원리 설명용이며 물리적 결과를 정확히 예측하지 않습니다.

최신 트렌드 화면은 버튼을 누르면 오늘 KST 범위의 SNS 게시물을 수집해 키워드를 집계합니다. Bluesky는 키 없는 공개 API, YouTube·Instagram은 키 없는 공개 HTML 크롤러를 사용합니다. 기존 RSS는 관리 화면의 별도 기능입니다. Instagram은 공개 HTML에 캡션·게시 시각이 없거나 로그인이 필요하면 수집하지 못하며, 성공으로 표시하지 않습니다. 공개 게시물 링크를 최대 8개 넣어 해당 페이지를 직접 읽을 수도 있습니다.

Gemini AI는 로컬 `.env.local` 또는 Render Environment에 `GEMINI_API_KEY`를 설정하면 기본 모델 `gemini-3.5-flash-lite`로 연결됩니다. `GEMINI_MODEL`로 모델을 바꿀 수 있습니다. 공개 버전에서도 베이킹 코치를 사용할 수 있으며 질문·최근 대화·현재 원본 레시피·참고 자료가 동의 후 Google에 전달됩니다. 키는 서버에만 저장합니다. 기존 `AI_API_KEY`, `AI_MODEL` OpenAI 설정은 로컬 실행에서 유지합니다. 실제 Gemini 답변은 본인 키 입력 후 검증해야 합니다. 자세한 설정은 배포안내.md를 확인하세요.

기록은 설정 화면에서 JSON 또는 사진 포함 ZIP으로 내려받을 수 있습니다. 코드 ZIP에는 개인 기록, API 키, 설치된 패키지와 빌드 결과를 포함하지 않았습니다.

## 검증 상태

핵심 도메인 검사 28개, 별도 테스트 DB를 사용한 API 검사 30개와 앞선 제작 빌드는 통과했습니다. 브라우저에서 3D 표시와 재료 저장도 확인했습니다. 그 후 들어간 최근 수정분의 최종 일괄 검증은 사용자의 요청에 따라 보류했습니다. 실제 제조, 실제 AI 호출, 사용자 3인 평가, 전체 접근성 검사를 완료했다고 주장하지 않습니다.

필요할 때 `npm test`, `npm run typecheck`, `npm run build`로 확인할 수 있습니다. `scripts/check-api.mjs`는 별도 검증 서버의 기본 포트 3211을 대상으로 하므로 일반 실행 중에는 실행할 필요가 없습니다.


## 이번 수정의 새 기능과 디자인

- 실패 역추적: 원인 후보를 관찰 일치도 순으로 표시합니다. 검증되지 않은 발생 확률은 만들지 않습니다.
- 쿠키 화학: 버터·설탕·소다 슬라이더와 설명용 쿠키 그래픽, 미검증 수정본 저장.
- 오븐 성격: 독립 온도계 측정 3회 이상을 이용한 보정 제안과 3×3 갈변 지도.
- 팬 변환: 원형·사각·머핀 칸의 반죽 충전 부피에 따른 재료량, 첫 관찰 시간 안내.
- 날씨: Open-Meteo 도시별 실외 온습도와 직접 측정한 실내 값의 안내.
- 오븐 생중계: 실제 카메라가 아닌 설명 애니메이션, 경과 시간, 색 질문, 다음 관찰 알림, 관찰 저장.
- 쌍둥이 실험: A/B 치수·사진 기록과 같은 배합·조건의 로컬 자료 집계. 전국 데이터는 아닙니다.
- GLB 교체: 연구실의 업로드 화면 또는 `public/assets/user-models`와 `content/models.json` 사용.
- 키치 디자인: `app/kitsch.css`에서 노랑·코발트·핑크, 스티커·체크무늬·굵은 테두리를 수정합니다.

새 기능의 화면은 `components/ScienceScreens.tsx`, 관찰 타이머는 `components/LiveBake.tsx`, SNS 화면은 `components/SocialTrends.tsx`에 있습니다. 계산·순위 규칙은 `lib/science.ts`, SNS 수집·집계는 `lib/social-trends.ts`, 추가 API는 `lib/feature-api.ts`에 모았습니다.

앞선 v2 제작 당시에는 실행하지 않았으며, 이후 사용자의 실행·오류 수정 요청으로 로컬 서버를 켜서 확인했습니다. 공개 HTML 크롤러 파서 검사 8개와 타입 검사를 통과했습니다. 실제 API 경로로 키 없이 YouTube 영상 4개 수집을 확인했고, Instagram은 공개 HTML에 필요한 데이터가 없어 실패 안내가 표시되는 것을 확인했습니다. 실제 연결 상태·검색 결과에 따라 수집 수는 달라집니다. 전체 기능에 대한 새 일괄 빌드·제조 검증을 완료한 것은 아닙니다. 사용자 GLB 원본은 별도로 보관하세요. 코드 ZIP에는 업로드 모델과 개인 기록을 넣지 않습니다.

### 공개 페이지 크롤러 수정

`lib/public-social.ts`에서 YouTube `ytInitialData`, Instagram 공개 JSON·JSON-LD·메타데이터를 해석합니다. 받은 스크립트를 실행하지 않으며 서버는 고정 SNS 호스트만 읽습니다. 로그인·접근 확인으로 이동하면 중단합니다. HTML 형식이 달라지면 파서를 수정해야 합니다. YouTube의 ‘3시간 전’ 같은 표시는 정확한 게시 시각이 아니므로 오차 범위 전체가 KST 오늘에 들어갈 때만 채택하고 화면에 ‘추정’으로 표시합니다. API 키 입력 없이 호출할 수 있다는 의미이며 항상 수집된다는 보장은 아닙니다.

### 제품명을 상단, 해시태그를 하단에 표시

상단은 제목·본문의 디저트 이름을 집계하고 하단은 실제 해시태그를 별도로 집계합니다. `content/trend-products.json`은 제품 이름·별칭 사전이며 유행 순위 목록이 아닙니다. ‘두쫀쿠/두바이 쫀득 쿠키’ 같은 별칭은 병합하고 ‘상하이 버터떡’에서 일반 ‘버터떡’을 다시 세지 않습니다. 실제 수집 자료에 없는 이름은 순위에 나타나지 않습니다. 본문에서 찾은 미등록 복합 제품명은 ‘자동 발견 후보’로 별도 표시하며, 완전한 한국어 개체명 인식 모델은 아니므로 이름 검토가 필요합니다. 제품명·해시태그를 클릭하면 각각 근거 게시물을 볼 수 있습니다. 이전 수집 자료도 다시 분석하지만 기존 수집 시각을 새 시각으로 바꾸지는 않습니다. 현재 표본의 언급 빈도이며 과거 동시간대 비교가 없어 상승률은 표시하지 않습니다.

### 최근 7일 · 고유 게시물 2,000개 목표

트렌드 버튼은 KST 오늘을 포함한 7개 날짜의 자료를 목표 2,000개로 수집합니다. `lib/social-job.ts`가 한 번에 작은 묶음을 조회하고 DB에 진행 상태를 저장합니다. 일시 정지·화면 이동·서버 종료 후 ‘이어가기’가 가능하고, ‘현재 모인 자료로 분석 마무리’로 목표 이전에도 분석할 수 있습니다. 화면이 닫힌 동안 계속 도는 백그라운드 작업은 아닙니다. 작업 시작 시 정한 기간과 종료 시각은 이어갈 때도 유지됩니다.

Bluesky는 공개 다음 페이지의 403 인증 제한을 확인했으므로 날짜별·검색어별 공개 첫 결과를 모읍니다. YouTube는 검색어별 공개 첫 결과를 모으며 Instagram 제한은 그대로 적용됩니다. 공개 전체 자료의 완전한 수집이 아니며 국내 자료만으로 구성한 표본도 아닙니다. ID·본문 중복, 기간 외, 베이킹소다 청소 등 잡음은 제외합니다. 확보할 수 있는 자료가 부족하거나 조회 한도에 닿으면 ‘목표 미달’로 표시하며 2,000개를 보장하거나 모자란 수를 채워 넣지 않습니다. 조회 요청은 작업당 최대 120개로 제한합니다.

분석 화면에서 ‘최근 7일 자료’와 ‘그중 오늘 자료’를 전환합니다. 상대 시각이 오늘 경계에 걸치는 영상은 오늘 집계에서 제외합니다. 2026-10-30 검증에서는 자동 테스트 54개·타입 검사·프로덕션 빌드·별도 DB의 API 검사 30개를 통과했습니다. 실제 주간 수집은 별도 검증 DB에서 게시물 2,069개(그중 기준일 373개)를 확보했습니다. 요청·재개·집계 관련 실제 응답 검사 8개도 통과했습니다. Instagram은 필요한 공개 데이터를 읽지 못해 집계되지 않았으며, 이 수량은 Bluesky·YouTube 자료입니다. 자료 수는 재실행 시 달라질 수 있습니다.

날짜가 바뀌면 기존 결과가 사라지는 문제를 수정했습니다. 마지막 결과를 보존하되 이전 기준일 자료라는 안내와 날짜를 표시합니다. 다음 날 수집을 이어가도 최초에 고정한 기간을 유지합니다. 동시 이어가기 요청·중복 수량·실패 출처 중단·목표 미달·중도 마무리에 대한 회귀 검사도 포함했습니다.

### 제과·제빵 필터와 Instagram 브라우저 수집

`lib/baking-relevance.ts`에서 게시물 관련성을 먼저 검사합니다. 쿠키런·쿠킹덤 같은 게임, 브라우저 쿠키, 청소·세탁·화학 용도의 베이킹소다, 성인 홍보, 고기·일반 요리 자료를 제외합니다. 해시태그는 제과·제빵 제품·기술·활동으로 확인된 표현만 허용합니다. 베이킹 글에 함께 붙어 있어도 일반 일상·지역·식품 태그는 순위에 넣지 않습니다. 규칙 기반이므로 새로운 표현을 빠뜨리거나 문맥을 오해할 가능성은 있습니다. 기존 저장 자료도 화면을 열 때 다시 필터링하며, 이전 수집 수가 줄어들면 목표 달성 여부를 다시 계산합니다.

Instagram은 HTML에 데이터가 없으면 `lib/instagram-renderer.ts`에서 별도의 Edge/Chrome을 실행해 JavaScript 렌더링 후 공개 게시물 링크를 자동으로 찾고 상세 페이지 메타데이터를 읽습니다. `playwright-core`와 설치된 Microsoft Edge 또는 Chrome이 필요합니다. 브라우저는 창 없이 실행되고 각 작업 후 닫히며 기존 사용자 프로필·쿠키·비밀번호는 사용하지 않습니다. 로그인·접근 확인이 요구되면 중단합니다. 브라우저가 없는 환경에서는 안내 오류가 나며 원격 배포용 환경 설정은 제공하지 않습니다.
